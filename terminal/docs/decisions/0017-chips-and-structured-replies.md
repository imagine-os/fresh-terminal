# 0017 — chips with types you can set, a glossary per box, and structured replies

Date: 2026-09-29. Model: Opus 5.5. Prompt: 0012.

- **Chip kinds (16):** action, date, time, person, org (brand/company), place, object, variable, list, number, money, url, page, nav, theme, entity. Each chip has a source (`local`, `model`, `glossary`, `user`), a probability `p`, alternative readings and an optional note or record ref.
- **Two taggers, merged.** The local tagger runs on every keystroke. The model tagger is on by default: after a 600 ms pause the app calls `POST /tag` (Gemini 2.5 Flash-Lite, strict JSON schema, all fields required). `mergeChips` joins readings for the same span, drops model chips that overlap local ones, and adds the rest.
- **Hoy.** The local tagger gives "Hoy" two readings. A possessive ("Hoy's") leans brand at 0.8; a capital mid-sentence leans brand; a following "a las" or "at" makes it a date. A chip is ambiguous when its second reading has p ≥ 0.25 within 0.35 of the first; it is drawn dashed with a "?". `POST /tag` asks Jev to settle ambiguous spans (one decisions call, one question per span) and the chip comes back with the winning reading; if Jev is unavailable the chip stays ambiguous for the user to settle. User-set and glossary chips are never ambiguous.
- **Glossary.** `glossary_term {text, type, note, case_sensitive}` per box, written by the `glossary.add` op (from the chip popover's "Always treat 'Hoy' as brand in this box"). It is applied after tagging (Unicode word boundaries; case-sensitive when the taught text has capitals) and sent with every tagger and router call.
- **Chip popover.** Click or focus + Enter. Readings first, then the full type grid, a value field (date and time pickers; record pickers for pages, menu items and themes), a note, and the glossary checkbox. 44 px targets, keyboard only works, Escape closes and returns focus, English and Spanish.
- **Chips reach the model as data.** The user message ends with `[chips] [...]` JSON including source; the system prompt says types with source `user` or `glossary` are the user's decision and must be trusted.
- **Super-CLI replies.** The model's `respond` tool returns typed blocks: summary, kv, table, steps (done ✓, active ✱, todo ○), list, code, diff, next (1–4 clickable commands that fill the composer), note, error. The app adds `diff` and `edits` (with Undo/Redo) from what it actually applied, and puts `next` last. Every reply has a header line: intent · model · time · cost. Plain text is the fallback when a model does not call `respond`. Replies are stored on the line as `blocks_json`.
