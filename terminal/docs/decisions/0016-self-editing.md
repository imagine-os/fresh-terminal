# 0016 — self-editing: the interface is data, changed only by ops

Date: 2026-09-29. Model: Opus 5.5. Prompt: 0011.

- **Everything on screen is a record in the box's store.** `shared/src/ui`: `nav_item` (recursive tree through `parent_id`; target is a box, page, URL or action; `javascript:` and `data:` URLs are refused), `page` with blocks (heading, text, list, card, button, table, image, embed), `box_ui` (layout sentence, theme id, style token overrides; `null` means the product or visitor default), plus the existing starters and canvas cards, and the new `glossary_term`. New boxes get a default menu (Library, Canvas, Plan). The same tables exist in the SpacetimeDB module (`nav_item`, `page`, `box_ui`, `glossary_term`, `edit_batch`, `line.blocks_json`) and in the local store.
- **Ops are the only way anything changes.** `shared/src/ops/schema.ts`: `nav.add/rename/move/retarget/remove`, `shell.set`, `theme.set`, `style.set`, `page.create/rename/add_block/update_block/remove_block/delete`, `card.add/remove`, `starter.add/remove`, `glossary.add/remove`, plus internal `*.restore` ops used only by inverses. Records are referenced by id or by label/title, so the model can say `parent: "Projects"`. `applyOps(state, ops, ctx)` is pure and atomic: if any op fails, nothing applies. It returns the new state, the inverse batch and a list of changes ("added 'Koi Pond' under 'Projects' in the sidebar"). `shell.set` merges a partial layout sentence into the current one (only the regions and sizes mentioned change) and rejects unknown words. Style tokens are limited to `--name` with values that cannot close a rule.
- **Undo is a stack of batches.** Each applied batch keeps its inverse. The Undo button on the "Edited: …" line, Ctrl/Cmd+Z (outside a field or in an empty composer) and the `edit.undo` action undo the newest batch; Shift adds redo. Assistant, local, chip, undo and redo edits are ledgered as kind `edit` (unit `op`, zero price); shortcut edits (T, the dev theme picker) are not.
- **The router does tool calling.** `POST /route` takes a snapshot of the box (menu, pages, layout, theme, themes, actions, boxes, starters, cards, glossary). Every op is a tool (`nav_add`, `theme_set`, …) plus `respond` for the structured reply; `tool_choice` is required. The router dry-runs the calls on the snapshot. If any call is invalid, it sends the reasons back once and asks for the complete corrected set; a second failure is reported as an error block and nothing is applied. The system prompt forbids telling the user to edit files. SSE adds `ops {ops, changes, rejected}` and `reply {blocks}`; `done` reports rounds, and the entry's cost is the sum of all rounds plus Jev.
- **Escalation.** Jev has an `edit_ui` choice. When it routes `edit_ui` below confidence 0.6, or the box has more than 40 menu items or 10 pages, the first round runs on `anthropic/claude-sonnet-5.5` instead of Haiku 4.5; the retry always uses Sonnet 5.5. Thresholds live in `router/rules.json` under `escalation`.
- **Own key gets the same turn.** `shared/src/agent/turn.ts` `runTurn()` is used by the router and by the browser-direct path, so both validate and retry the same way.
- **The client re-applies.** The app applies the router's ops through `store.applyOps` (atomic again, against the live state) and reveals the changed region with the CRT beam. If the live state moved since the snapshot, the batch fails whole and the reply says so.
- Rejected: letting the model write component code or CSS files (not undoable, not checkable); a separate "edit mode" (every prompt can edit).
