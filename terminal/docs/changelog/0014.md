## Shipped

- Research: Clerk Billing does subscriptions only; usage billing is "not yet". Recommendation: Stripe Checkout prepaid credit packs (decision 0024, with sources).
- D1 migration `0003_billing_and_grants.sql`: `accounts.billing_threshold_micro` (default $5), `billing_state` (`free` | `needs_payment` | `active`), `paid_micro`; new tables `credit_grants`, `invite_codes`, `invite_redemptions`.
- Router (`router/src/credits.ts`): the credit limit is min(grant, threshold); past it `402 payment_required` (threshold) or `402 account_credits_exhausted` (grant), and `billing_state` becomes `needs_payment`. `GET /credits` carries `billing { state, threshold_micro, credit_limit_micro, paid_micro, provider }`. Your key is never metered, so never blocked.
- Router (`router/src/admin.ts`): admin gate (`ADMIN_USER_IDS` var, `ADMIN_EMAILS` secret via the Clerk Backend API), `POST /admin/grant`, invite codes (`POST /admin/invites`, `/admin/invites/disable`, `POST /credits/redeem`), `POST /admin/account` (threshold, state), read-backs (`/admin/overview`, `/admin/grants`, `/admin/invites`, `/admin/ledger`, `/admin/accounts`, `/admin/whoami`). Every credit is a `credit_grants` row plus a `credit` ledger entry.
- Payments hook: `POST /billing/checkout` (Stripe Checkout, `501 not_wired` without keys) and `POST /billing/stripe/webhook` (signature checked, credits once). Not tested against live Stripe.
- App: tray tiles **Top up / add payment** (says "not wired yet" until the router reports Stripe) and **Invite code** (signed in). Transcript line for `payment_required` (EN/ES). Actions `billing.topup` (not wired) and `invite.redeem`.
- Hub: `app/hub/index.html` + `app/src/hub/*` (a second Vite entry), `scripts/build-hub.ts` + `scripts/hub-data.ts` (library, Canon, records, wiki index, plan, items, secrets checklist into `dist/hub/data/`, only with `HUB_DATA=1`), `app/hub/items.json` (what the hub lists). Site Worker gates `/hub/data/*` and `/hub/api/*` through the router (service binding `ROUTER`).
- Workflows: `site-deploy` builds the hub data and a names-only secrets checklist; `router-deploy` pushes `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `ADMIN_EMAILS` when they exist; new `hub-smoke` (throwaway admin and friend on the Clerk dev instance: 401/403 checks, a grant, an invite code, the 402 gate, cleanup).
- Tests: admin gate (401/403/id/email/unverified), grants by email and id with ledger chaining, invite codes (uses, once per account, expired, switched off), the $5 gate, the not-wired hook, the Stripe webhook signature and single credit; the site Worker's hub gate; hub data parsed from the real docs. `scripts/qa-hub.mjs`: 360–3840 px, no overflow, every control ≥ 44 px.
