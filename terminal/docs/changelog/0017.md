# 0017 — the account window fits, phone to 4K

Date: 2026-09-29. Model: Opus 5.5. Prompt: Canon 93 ("problem" and a screenshot of the clipped account window, [message](https://aluzinaworkspace.slack.com/archives/C0C2YAS5TL5/p1790659765100189?thread_ts=1790634517.611669&cid=C0C2YAS5TL5)). Canon C-099. Page doc `pages/auth.md`.

## Cause

`clerkAppearance.ts` (C-084) put the sign-in card width, `min(100vw - 2rem, clamp(25rem, 16rem + 10vw, 46rem))`, on the global `cardBox` element. Every Clerk component uses `cardBox`, so the account window (UserProfile, nav plus page, which Clerk sizes at 55rem) was forced to ~447 px at 1908 px wide and its page to ~200 px.

## Shipped

- `app/src/auth/clerkAppearance.ts`: the width moved to `signIn` and `signUp` only (`AUTH_CARD`). `userProfile` and `organizationProfile` get `PROFILE_ELEMENTS`: card `min(100vw - 2rem, max(64em, 50vw))` by `min(100dvh - 3rem, 48em)`, Clerk's fixed `min(44rem, 100% - 3rem)` modal height follows the card, the root box follows too. Long emails, usernames and names wrap instead of ending in "…". 44 px targets for the nav buttons, section buttons ("Update profile", "Add email address"), "…" menus, menu items, the mobile menu button and "Show password" (it was 32×38 on sign-in).
- `scripts/check-clerk-modal.ts` (`pnpm check:clerk`): sign-in and account window at seven widths (see `pages/auth.md`).
- `.github/workflows/clerk-modal.yml`: runs the check after each `site-deploy` and on demand with a throwaway development user and organisation; deletes them and any D1 rows for them; optional inputs clean up a hand-made test user.
- `app/src/auth/clerkAppearance.test.ts`: fails if the width returns to the global card or the account window loses its size or targets.

## Gate

- Before push: typecheck clean; vitest all green; build green; `check:responsive` 56 of 56 (eight pages at seven widths); `check:clerk` 14 of 14 (sign-in and account window at 360, 390, 768, 1280, 1920, 2560, 3840) on a local build, signed in as a throwaway development user.
